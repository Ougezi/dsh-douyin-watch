## 实测发现（都进了代码或文档）

1. 卡片必须**页面内合成 click** 才开播放器；物理鼠标事件无效。
2. 打开后的 URL 带 `?modal_id=`，是稳定视频 ID，也能直接重开。
3. 推荐流会**预加载隐藏 `<video>`**，只看 `videoCount` 会把预加载误判成播放器。
4. 播放器有**首次使用引导浮层**（"我知道了"），不摘掉会把引导拍成"帧"。
5. **搜索与评论都要登录**：未登录只有登录墙，评论 DOM 为 0。
6. 匿名浏览不弹登录框，所以"没弹窗"不能当"已登录"——改用会话 cookie 判断。
7. 创作者中心未登录落地页也含"达人作品管理"，关键词判定会误报。

## 没做的，以及原因

| 项 | 为什么 |
| --- | --- |
| `ops_comment` / `ops_reply` / `ops_dm` / `ops_publish` | 全部需要登录，且**写操作不可回滚**。登录后读评论已实现（`kb_comments`），但发表类动作仍未实现：不发布无法验证的写操作代码。闸门（授权/额度/串行锁/幂等/回执核验）已就绪并有测试，等本人逐条验收后再加。 |
| `kb_comments` | 已实现（v0.3.0）：登录后读独立视频页的评论。**发表评论/回复仍未实现**（写操作）。 |
| ASR 语音转写 | 计划里就排除：会引入 Python/ONNX 重依赖，与"零依赖"取舍冲突。留了适配器位置。 |
| `captcha` 自动处理 | 安全红线：遇验证码停下等人，不做绕过。因此该路径只能人工验，测试里明确标注未覆盖。 |

## 下一步（需要用户参与）

1. **登录一次**：调 `dy_login`，在弹出的窗口扫码；之后 `kb_search` 可用。
2. 登录后若要写操作：先只开 `ops_like` 试一条，确认幂等与回执，再逐级放开其他动作。
3. 抖音改版时：跑 `dy_diagnose` 拿到真实结构，再改对应 `adapters/douyin/*.js`。

## 成本

- `cards` 模式与日报：0 模型调用。
- `play` 模式：每抓一帧记 1 次模型调用（`dailyModelCalls` 管住）。
- 只读层 `kb_*`：只处理文本与本地文件，0 模型调用。
